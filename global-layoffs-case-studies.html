Case Study

Global Layoffs Analysis - Turning raw data into a clear story.

A SQL-driven analysis of global layoffs between 2020 and 2023, cleaned and explored in MySQL, then shaped into Power BI and Tableau dashboards that reveal what changed across industries and why it mattered.

Project Overview

This project set out to make sense of a large, messy public dataset documenting layoffs across companies and industries worldwide from 2020 to 2023. The goal was to clean the data properly in SQL first, then build visual dashboards that turned scattered numbers into a readable narrative about the state of the job market.

Problem

The raw dataset was inconsistent: duplicate entries, blank fields, inconsistent date formats, and company names logged in different ways. On its own, the data was too noisy to analyse or trust, let alone present to anyone else.

Solution

  • Cleaned and standardised the dataset entirely in SQL before any visual work began.
  • Removed duplicates and handled null values without losing meaningful records.
  • Standardised company, industry and country naming for consistent grouping.
  • Wrote exploratory queries to surface trends by industry, country and time period.
  • Connected the cleaned data to Power BI and Tableau to build interactive dashboards.

Technologies

  • SQL (MySQL, PostgreSQL)
  • Power BI
  • Tableau
  • Git & GitHub

How It Works

  • Raw CSV data is imported into a SQL database for cleaning.
  • Duplicate rows are identified and removed using window functions.
  • Missing values are addressed with joins against reference data where possible.
  • Cleaned tables are queried to explore trends by industry, stage and region.
  • Results are connected to Power BI and Tableau for dashboard visualisation.

Key Features

  • Fully cleaned, query-ready dataset.
  • Industry and region-level breakdowns of layoffs over time.
  • Interactive Power BI and Tableau dashboards.
  • Clear before-and-after view of raw versus cleaned data.

Challenges

The hardest part was deciding what "clean" actually meant for this dataset — some blank fields were genuinely missing information, while others represented a real zero. Working through SQL first, before touching any visuals, made it possible to make those calls deliberately rather than guessing at the dashboard stage.

What I Learned

  • Data cleaning techniques in SQL, including deduplication and null handling.
  • Writing exploratory queries to find patterns before visualising anything.
  • Building dashboards that communicate a clear story, not just numbers.
  • The value of separating data preparation from data presentation.

Project Outcome

The result is a dashboard-ready dataset and a set of visuals that make it easy to see how layoffs shifted across industries and time. The project sharpened my SQL fundamentals and showed me how much a clear data story depends on the quality of the cleaning that happens before a single chart is built.
